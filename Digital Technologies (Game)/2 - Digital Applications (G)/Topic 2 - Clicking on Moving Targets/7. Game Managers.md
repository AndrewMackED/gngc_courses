# 7. Game Managers
Ok, so now we have a lot of our game's functionality working, all we need to do now is **make it a game**. 

When we're making a game that we want to actually record progress there are a lot of variables that we need to keep track of. 

Now, there are a few different places where we can keep track of these variables, the top three are:
- On the Player (or sub-player scripts like Weapon scripts)
- On a Level Manager, that keeps track of local within-level variables
- On a Game Manager, that keeps track of global variables, that will need to be persistent across levels

## A Level Manager for our FPS
Now we get into the practical part, how are we going to create a Level Manager for our FPS.
We're going to start off by finding the root node of our scene:
- Rename the root node of the scene to be called "Level Manager"
- Create a new blank script on the root node
- Create a new Timer node in your scene as well, rename it "Level Timer", and set it up near the top of the tree so it's logically near all the Environment and Lighting setup

> [!NOTE] Reusability
> We're going to be designing this script in such a way that is going to let us reuse it, so it should be automatically identifying the number of enemies in the scene, and anything you want to be achieved.

### My Level's Goals
I'm going to be designing this as a "Timed Elimination of Targets" minigame, where the goal is to eliminate all the targets as quickly as possible and try to achieve the fastest time. This is going to allow players to have some replayability to optimise their time to complete the level, and compete with their friends!

So let's kick of our Level Manager script, but creating the variables I'll need to keep track of. I should note, this is a really good time to be adding a little bit of structure to a script like this, I've grouped some variables here to make it nicer to look at.

```gdscript
extends Node

# Timing
var time : float = 0

# Target Tracking
var targets: Array = []
var starting_targets: int = 0

# State Tracking
var is_game_over: bool = false
```

So here's the deal:
- We're just going to keep track of the time in the game by adding the `process` variable `delta` to the game time every frame. Delta is after all the *time between frames* so we can just take advantage of that.
- In terms of tracking the targets, we're going to fill in a list of targets when the game starts, and then store the length of it in the `starting_targets` variable.
	- When enemies die, they will automatically remove themselves from the `targets` list by just *not existing anymore*. So if we want to know how many targets are remaining, we can check the length of the list
	- If we want to know how many we've killed, it's going to be `starting_targets - len(targets)`
	- You can of course store the variables separately if you like though!
- We're also going to just keep a simple variable for the game state right now. We can expand on this later if we like!

## How do we know how many enemies there are in the scene?
Groups my friend, groups.
This is a feature that I have somehow not approached all year up to this point, but they are **very** useful.

We're going to make a new "targets" group. 
![[create_group.gif]]
**Make sure that if it isn't meant to be a target, then this checkbox isn't True!**

Steps:
1. Groups (top-right next to Signals)
	1. create new group "targets"
2. In Enemy Script
	1. add `add_to_group("targets")` to the top of the `ready` function

Now we can go back to our Level Manager script, to work out how many enemies are inside the group!
THere's a problem though.
*We need to make sure that when we're getting the list of nodes in the group, it needs to happen **AFTER** the enemy scripts add them to the group*

We're going to implement a **deferred function**.
Add this to the Level Manager script

```gdscript
func _ready():
	call_deferred("check_targets")
	
func check_targets():
	targets = get_tree().get_nodes_in_group("targets")
	starting_targets = len(targets)
	print(targets)
	
```

This is going to run the check_targets function **after** the ready function finishes, technically it runs on the first process frame. You can remove the **print** command once you've tested and confirmed that all the enemies you're expecting are in there, and none that you're not expecting!

## I made a mistake...
Take a read of this **completely incorrect statement** from up above when I was deciding how to organise our variables:
> - When enemies die, they will automatically remove themselves from the `targets` list by just *not existing anymore*. So if we want to know how many targets are remaining, we can check the length of the list
> - If we want to know how many we've killed, it's going to be `starting_targets - len(targets)`

So, what actually happens when the enemies die:
- They don't actually remove themselves from the `targets` list, they are still in there, but listed as a `Freed Object`. So after I killed the three enemies in my game, this is what my `targets` list looked like
	- `[<Freed Object>, <Freed Object>, <Freed Object>]`
- So the way I was planning doesn't actually work!

### What do we do instead?
We're going to use Signals, like I probably should have done to begin with, but I was trying to be sneaky!

We've used signals a lot before, but this time the signals are going to automatically connect themselves in the code, and they will link to the level manager in their scene.

Back in the Enemy script:
```gdscript
#Add this up the top near your variables
signal target_destroyed

#Edit your take_damage function to emit the signal when destroyed
func take_damage(dmg : int):
	hp -= dmg
	if hp <= 0:
		target_destroyed.emit()
		queue_free()
		
```

And now take a look at the current full version of the Level Manager script;
```gdscript
extends Node

# Timing
var time : float = 0

# Target Tracking
var targets: Array = []
var starting_targets: int = 0
var targets_destroyed : int  = 0

# State Tracking
var is_game_over: bool = false

# UI Display Labels
@onready var lbl_time = $CanvasLayer/LblTime
@onready var lbl_score = $CanvasLayer/LblScore


func _ready():
	call_deferred("setup_targets")
	
func setup_targets():
	targets = get_tree().get_nodes_in_group("targets")
	for t in targets:
		if t.has_signal("target_destroyed"):
			t.target_destroyed.connect(_on_target_destroyed)
	starting_targets = len(targets)
	lbl_score.text = "Targets: {destroyed} / {total}".format({"destroyed": targets_destroyed , "total": starting_targets})
	print(targets)
	
func _process(delta):
	if not is_game_over:
		time += delta
		lbl_time.text = "Time: %.2f" % time

func _on_target_destroyed():
	targets_destroyed += 1
	lbl_score.text = "Targets: {destroyed} / {total}".format({"destroyed": targets_destroyed , "total": starting_targets})
```


## Ending the Game
Now we are tracking all the game variables that we need to know about, let's make a Game End screen!

First, I'm going to design one, and then make it not visible while the game is running:
![[HUD_END_Design.png]]![[HUD_END_Nodes.png]]

Now we just need the game to be checking for when the game ends, and to run the relavent commands when it does. Please add the new code below:
- The first function is an updated version of the `_on_target_destroyed` function, that will check for whether the game should end (If the player has destroyed all the targets)
- The new `game-end` function will be used to wrap up the game!


```gdscript
func _on_target_destroyed():
	targets_destroyed += 1
	lbl_score.text = "Targets: {destroyed} / {total}".format({"destroyed": targets_destroyed , "total": starting_targets})
	if targets_destroyed == starting_targets:
		game_end()
		
func game_end():
	is_game_over = true
	game_end_screen.visible = true
	$GameEndScreen/final_time.text = "Time: %.2f" % time
```

Don't forget to add the reference to the `game_end_screen`
```gdscript
@onready var game_end_screen = $GameEnd
```
