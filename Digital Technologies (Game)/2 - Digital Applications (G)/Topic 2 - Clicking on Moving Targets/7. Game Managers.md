When we're making a game that we want to actually record progress there are a lot of variables that we need to keep track of. 

Now, there are a few different places where we can keep track of these variables, the top three are:
- On the Player (or sub-player scripts like Weapon scripts)
- On a Level Manager, that keeps track of local within-level variables
- On a Game Manager, that keeps track of global variables, that will need to be persistent across levels

## A Level Manager for our FPS
Now we get into the practical part, how are we going to create a Level Manager for our FPS.
We're going to start off by finding the root node of our scene:
- Rename the root node of the scene to be called "Level Manager"
- Create a new blank script on the root node
- Create a new Timer node in your scene as well, rename it "Level Timer", and set it up near the top of the tree so it's logically near all the Environment and Lighting setup

> [!NOTE] Reusability
> We're going to be designing this script in such a way that is going to let us reuse it, so it should be automatically identifying the number of enemies in the scene, and anything you want to be achieved.

### My Level's Goals
I'm going to be designing this as a "Timed Elimination of Targets" minigame, where the goal is to eliminate all the targets within a set period of time. This is going to allow players to have some replayability to optimise their time to complete the level, and compete with their friends!

So let's kick of our Level Manager script, but creating the variables I'll need to keep track of. I should note, this is a really good time to be adding a little bit of structure to a script like this, I've grouped some variables here to make it nicer to look at.

```gdscript
extends Node

# Timing
@onready var level_timer = $"Level Timer"

# Target Tracking
var targets: Array = []
var starting_targets: int = 0

# State Tracking
var is_game_over: bool = false
```

So here's the deal:
- We're going to handle the timing with a Timer node, they're so easy to work with so we'll take advantage of that
- In terms of tracking the targets, we're going to fill in a list of targets when the game starts, and then store the length of it in the `starting_targets` variable.
	- When enemies die, they will automatically remove themselves from the `targets` list by just *not existing anymore*. So if we want to know how many targets arre remaining, we can check the length of the list
	- If we want to know how many we've killed, it's going to be `starting_targets - len(targets)`
	- You can of course store the variables separately if you like though!
- We're also going to just keep a simple variable for the game state right now. We can expand on this later if we like!
