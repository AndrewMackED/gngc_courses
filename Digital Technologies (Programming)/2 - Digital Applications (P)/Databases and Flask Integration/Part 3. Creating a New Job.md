### Select Boxes and Flask
These are extremely useful! Before I explain anything, let's take a look at the end goal:
![[select_box_demo.gif]]
Here, you can see that I'm displaying the contents of my User and Machine tables inside of these two drop-down boxes, called `select` inputs in HTML.

There's actually a very nice trick here. Because the system and the user both want different things. Let's talk about the user selection:
- The SYSTEM wants the `user_id`
- The USER wants to select by the user's `name`

So what do we do? Take a look at the code below:
```html
<label for="user">User</label><br>
<select id="user" name="user">
    {% for u in users %}
        <option value="{{u.id}}">{{u.name}}</option>
    {% endfor %}
</select>
```

- The Select tags create the actual input control, and we're going to refer to the `user` form input on the Python side later
- We then fill the contents of the form by looping through the User table's data
- Here's the neat part:
	- You can see that we're setting the `value` on each of these options to be the `user_id` but we're setting the HTML display text to be the user's `name`! 
	- This means that on the backend when we read the data, it will be the user_id, but on the front end, the user will be selecting the user's name.
	- Making everyone happy. ***It's what we do***.

Add the code above to your Form, and  **create the same for your Machines**

### Textarea inputs
Text Areas are useful for multi-line inputs, and I think this is probably the input type we should be using for the job's *description*.
For context, here is my Text Area for a description, and then just a simple Text Input for the Material.
![[text_areea_eg.png]]

Sometimes a laser or 3D print job can take a bit of explaining, so making sure user's have a decent space for their explanation will help make sure they feel comfortable to provide that detail
> [!NOTE] Users and Inputs
> If users are only provided with a small area, they're going to try to summarise their job's information, but we kinda want the details!
> Users will usually treat the input size as a suggestion, and we should be using the input size as a suggestion!

So the HTML for a text area is pretty simple, I've included the regular text input for the material here as well.
**Add this to your form!**
```html
<label for="description">Explain the item you are asking to be manufactured</label><br>
<textarea id="description" name="description" rows="4" cols="80"></textarea>
<br><br>
<label for="material">Preferred Material and/or Colour</label><br>
<input id="material" name="material"></input>
```
You can see that we're setting the amount of rows and columns the input has, that's useful! That's the way that the sizing for Text Areas is handled (although you can use CSS to set the width and heigh in other ways. 
>Columns is measured in *characters*, so by setting this to 4 rows and 80 columns, we're creating a text field that's designed for 320 characters (though overflow is allowed)

Anyway, here's the mildly annoying thing about text areas though, take a look at this, in particular the **font**

![[text_area_styling.png]]

I have full global styling applied to everything to set the font-family to Arial, but IT DOESN"T APPLY IT TO TEXT AREAS FOR SOME REASON!
You should go and add this to your CSS file, and any text areas will get the same styling as everything else.
```css
select, input, textarea{
    font-family: inherit;
    padding: 5px;
}
```
This will make any select boxes, inputs, and textareas all inherit the font-family, and it will also give them all 5px of padding, which just makes everything feel a little nicer.

### Date Pickers
Date pickers are very cool! They're actually extremely simple to use, and there are some extra little tweaks you can make to have them really work for you. 

Here's the default HTML:
```html
<label for="date_required">Select the date you need the item by</label><br>
<input type="date" id="date_required" name="date_required"></input>
```
You can see there isn't much to the actual input. Just the input tag and then the Type being set to date, and then the required ID and Name that we should be putting on all our inputs.

You can also add Minimum and Maximum attributes to the element, so users can only choose dates within a specific range. Unfortunately to do the obvious thing of "make TODAY the minimum date", it does require a couple lines of Javascript. They're simple lines though! You just need to add this code snippet to the bottom of your HTML file:

```html
{% block scripts %}
<script>
    // Get today's date in local time ISO format (YYYY-MM-DD)
    const today = new Date().toLocaleDateString('en-CA');
    document.getElementById('date_required').setAttribute('min', today);
</script>
{% endblock %}
```

## 3. Handling the Form Data
Great! That wasn't exactly a small process, but we're getting there!
All we need to do now is to handle the form data on the backend, and store the job in the database. Simple right? It's actually not too bad.

Let's add this to your `create_job` route, above the Machine and User queries:
```python
if request.method == "POST":

	today = datetime.now().date()
	
	new_job = Job(
		user_id=request.form["user"],
		machine_id=request.form["machine"],
		material=request.form["material"],
		description=request.form["description"],
		date_required=request.form["date_required"],
		date_logged=today,
		completed=0,
	)
	db.session.add(new_job)
	db.session.commit()
	
	return redirect(url_for("index"))
```

Also, if you haven't imported `datetime` yet, go to the imports at the top of your code and do so!
```python
from datetime import datetime
```

So, notes on the code above:
- We're mostly taking the data from the form, and saving it in a `new_job` variable that will then get added to the database as a new record (exactly the same as creating a new user)
- There are two fields that aren't coming from the form though
	- `date_logged` is being set by the `today` variable that we're creating just above. Fairly simple stuff, I think you can see what it's doing by looking at it
	- `completed` is being set to `0` (false), because that's the default value for the field!
- Just like when we created a new user, our users are going to be redirected to the Index after completing the form.
